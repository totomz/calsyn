**Goal:** Every calendar the Operator owns shows the busy slots of the other calendars, so colleagues on any
account see the real availability and the Operator gets notified on every client.

## Context
The Operator has meetings spread over several accounts (Exchange, Google, ...). Each account only knows its own
events, so colleagues book over busy slots and notifications reach only one client. The previous scripts
(`calsync.py`, `google-sync.gs`) required handling credentials per provider and have been dropped. Calendar.app
already authenticates and syncs every account, so the store it exposes is the single place to read and write.

## Objectives

**Functional goal:** The Operator declares calendars and one-way jobs `source → destinations` in a YAML file.
For each job, every source event inside a time window appears as a clone in each destination, and clones follow
moves and deletions of their source. Calendar viewers on the destination accounts see the busy slots, with title
and description only when the job asks for them.

**Architectural goal:** A single Swift executable (`calsyn-cli`) talks to the calendar store through EventKit and
never touches credentials. The `reconciler` is pure logic over the `calendar-store` abstraction, so it is
tested against an in-memory fake; `runner` serialises reconciles triggered by startup, store changes and a 5 min
timer; `launch-agent` keeps the process alive in the user session through launchd.
